# 1. Как выложить сайт в интернет: GitHub → Cloudflare (бесплатно, без домена)

Время: 30–40 минут. Платить и привязывать банковскую карту не нужно. Домен покупать не нужно: Cloudflare выдаёт бесплатный адрес `*.workers.dev`.

## Что понадобится
- Электронная почта (лучше отдельная, только для сайта).
- Аккаунт на **github.com** (хранит код сайта) и на **cloudflare.com** (запускает сайт).
- Менеджер паролей или тетрадь для записи паролей (обязательно — см. раздел «Что хранить»).

---
## Шаг 1. Загрузите код на GitHub
1. Зарегистрируйтесь на github.com (Sign up), подтвердите почту. Включите двухфакторную защиту: Settings → Password and authentication → Two-factor authentication.
2. Нажмите **+** (справа вверху) → **New repository**. Имя: `svyazano`. Доступ: **Private** (приватный; код не содержит паролей, но публиковать его незачем). Create repository.
3. Распакуйте архив с проектом на компьютере. Откройте папку: в ней должны лежать сразу `wrangler.jsonc`, `package.json`, папки `src`, `public`, `docs` и др. (а не одна папка внутри папки).
4. На странице нового репозитория нажмите **uploading an existing file**, перетащите в окно **всё содержимое папки** (файлы и папки) и дождитесь загрузки. Внизу нажмите **Commit changes**.
5. Проверьте: в корне репозитория виден файл `wrangler.jsonc`. Если он внутри вложенной папки — загрузите заново содержимое.

> Скрытые файлы (`.gitignore`, `.dev.vars.example`) при перетаскивании могут не загрузиться — это нормально, сайту они не нужны.

## Шаг 2. Подключите GitHub к Cloudflare
1. Зарегистрируйтесь на dash.cloudflare.com (Sign up) → подтвердите почту. Включите двухфакторную защиту: My Profile → Authentication.
2. Слева выберите **Workers & Pages** (в новых версиях панели — «Compute» → «Workers & Pages») → **Create application** → **Import a repository** (или «Connect to Git»).
3. Разрешите доступ к GitHub (Install & Authorize), выберите репозиторий `svyazano`, Next.
4. Настройки сборки:
   - **Project name / Worker name:** `svyazano` — **должно совпадать** со строкой `"name"` в файле `wrangler.jsonc` (иначе сборка завершится ошибкой). Если хотите другое имя — измените `"name"` в `wrangler.jsonc` на GitHub (значок карандаша) и укажите то же имя здесь. Имя станет частью адреса сайта.
   - **Build command:** оставьте пустым. **Deploy command:** `npx wrangler deploy`. **Root directory:** `/`.
5. Нажмите **Save and Deploy**. Cloudflare соберёт проект (1–3 минуты). При первом запуске система может предложить выбрать **поддомен аккаунта** для `workers.dev` — придумайте любое слово латиницей: оно войдёт в адрес сайта.
6. В этом архиве уже указана существующая база D1 `svyazano-db` и её ID. Не создавайте новую базу и не меняйте привязку `DB`.

Адрес вашего сайта: Worker `svyazano` → **Settings → Domains & Routes** → строка `workers.dev` (например `https://svyazano.ivanova.workers.dev`).

## Шаг 3. Задайте секреты (без этого админка не откроется)
Секреты — это логин и пароль администратора и «ключ сайта». Их нельзя хранить в GitHub, поэтому они задаются в панели Cloudflare.

1. Worker `svyazano` → **Settings → Variables and Secrets → Add**.
2. Добавьте три записи, **тип — Secret** (не «Text»):

| Имя | Что это | Требование |
|---|---|---|
| `ADMIN_LOGIN` | ваш логин для входа | любой, например `masha-knit` |
| `ADMIN_PASSWORD` | пароль администратора | **не короче 14 символов**; лучше случайный из менеджера паролей |
| `APP_SECRET` | ключ защиты (хеширование, шифрование) | **не короче 32 символов**, случайный |

Как получить случайный `APP_SECRET`: менеджер паролей («сгенерировать пароль, 40 символов») или в Windows PowerShell: `[guid]::NewGuid().ToString() + [guid]::NewGuid().ToString()`; на Mac/Linux в терминале: `openssl rand -hex 24`.

3. Нажмите **Deploy** (или Save and deploy). **Сохраните все три значения в менеджере паролей** — Cloudflare потом их не покажет.

> ⚠️ Если изменить `APP_SECRET` после того, как клиенты оставляли почту (режим со сбором контактов), прежние зашифрованные почты прочитать станет нельзя. Меняйте только в случае компрометации.

## Шаг 4. Проверьте сайт
1. Откройте адрес сайта: должна открыться главная. Каталог пока пустой — это нормально.
2. Откройте `…workers.dev/admin`, войдите логином и паролем из шага 3.
3. Во вкладке **Игрушки** будут 3 демо-игрушки (скрытые). Отредактируйте, добавьте фото, поставьте «Показывать на сайте» → Сохранить → обновите главную страницу.
4. Вкладка **Настройки** — заполните сведения о продавце и контакты (это обязательно для реального сайта, см. docs/03).
5. Отправьте тестовое обращение со страницы «Поддержка» и ответьте на него из админки.

Подробно о работе в админке — в [docs/02](02-ИНСТРУКЦИЯ-АДМИНИСТРАТОРА.md).

## Если сайт открывается пустым экраном

Новая версия сначала отображает дизайн сайта, даже если API временно не отвечает. Если появляется уведомление «Каталог временно недоступен», проверьте:

1. В Cloudflare откройте **Workers & Pages → ваш Worker → Settings → Bindings** и убедитесь, что есть binding типа **D1 database** с именем переменной `DB`.
2. Проверьте, что binding `DB` указывает на созданную базу D1, а не просто объявлен в конфигурации без привязки к реальной базе.
3. Откройте раздел **Logs / Observability** у Worker и проверьте ошибки запросов `/api/toys` и `/api/site`.
4. После исправления binding выполните повторный Deploy и обновите страницу с полной перезагрузкой.
5. Если главная страница не открывается вообще (ошибка Cloudflare 1101/1102/1016 или 404), проверьте адрес Worker, состояние последнего Deploy и что `public/index.html` находится в каталоге статических assets.

В браузере можно открыть `/api/toys` и `/api/site`. При исправном подключении они должны вернуть JSON; `/api/toys` возвращает массив игрушек, а `/api/site` — настройки сайта. Если возвращается ошибка 503 о неподключённой D1, проблема в binding базы, а не в дизайне.

## Если при развёртывании возникает ошибка привязки D1
Проверьте, что в `wrangler.jsonc` сохранены имя `svyazano-db`, ID существующей базы и binding `DB`. Не создавайте новую базу.
1. Cloudflare → **Storage & databases → D1 → Create database**. Имя: `vyazanye-db`. Откройте её и скопируйте **Database ID**.
2. На GitHub откройте `wrangler.jsonc` (карандаш) и замените строку про базу на:
   `"d1_databases": [{ "binding": "DB", "database_name": "svyazano-db", "database_id": "94dd4b1f-c0d9-4174-aa6d-4d532b3d0142" }],`
3. Commit changes → сайт пересоберётся сам.

## Как обновлять сайт
- Любое изменение файла на GitHub (карандаш → Commit changes) автоматически запускает новую сборку и публикацию за 1–2 минуты.
- Изменить тексты на главной (заголовки, «Частые вопросы», шаги «Как заказать») можно в файле `public/app.js`; цвета — в начале `public/style.css`.
- Откат: Worker → **Deployments** (Versions) → выберите прежнюю версию → Rollback.
- Игрушки, контакты, обращения, данные продавца **обновлять через GitHub не нужно** — они меняются в админке и хранятся в базе.

## Лимиты бесплатного тарифа (проверено по документации Cloudflare)
- Обращения к коду сайта: **100 000 в день**, 10 мс процессорного времени на запрос. Статические файлы (страницы, скрипты, стили) отдаются бесплатно и без ограничений.
- База D1: 5 млн прочтений строк и 100 тыс. записей в день, 5 ГБ; размер одной базы — до 500 МБ.
- Что будет при превышении: до 00:00 UTC (03:00 по Москве) API перестанет отвечать. Для небольшого магазина этого с большим запасом хватает (каталог — одна быстрая выборка).
- Фотографии хранятся в базе (до 1 МБ каждая на сервере; админ-панель автоматически уменьшает большие изображения до 1800 px и сжимает их). Для одной игрушки можно загрузить до 8 фото.

## Локальный запуск и проверка (для разработчика)
Node.js 22.13+. `npm install` → `cp .dev.vars.example .dev.vars` (впишите значения) → `npm run dev` → http://localhost:8787. Проверка: `npm test`.
Альтернатива GitHub: `npx wrangler login` → `npx wrangler deploy`; секреты: `npx wrangler secret put ADMIN_PASSWORD` (и так же для остальных).

## Что нужно хранить
| Что | Где | Зачем |
|---|---|---|
| Логин/пароль GitHub и Cloudflare + коды двухфакторной защиты | менеджер паролей, резервные коды — на бумаге | доступ к сайту и коду |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `APP_SECRET` | менеджер паролей | Cloudflare их не покажет повторно |
| Адрес сайта и имя воркера | записная книжка | |
| Код сайта | репозиторий GitHub (и копия архива у вас на компьютере) | восстановление |
| Копия базы (игрушки, фото, настройки) | файл `backup.sql` раз в месяц | `npx wrangler d1 export <имя-базы> --remote --output backup.sql` (имя базы — в Cloudflare → D1) |

## Частые проблемы
| Симптом | Причина и решение |
|---|---|
| Сборка в Cloudflare падает | имя воркера не совпадает с `"name"` в `wrangler.jsonc`, или файл лежит во вложенной папке репозитория |
| В админке «Не заданы секреты…» (503) | не добавлены `ADMIN_LOGIN`/`ADMIN_PASSWORD` или тип записи «Text» вместо «Secret» |
| «Пароль слишком короткий» | `ADMIN_PASSWORD` короче 14 символов — задайте длиннее |
| «Сайт ещё не настроен: добавьте APP_SECRET» | нет секрета `APP_SECRET` (32+ символа) |
| «Не подключена база данных D1» | см. «Если база не создалась» |
| «Слишком много попыток» (429) | 5 неверных паролей: подождите 15 минут |
| После смены секрета пропал вход | выйдите и войдите заново |
| Ошибка 1102 «exceeded resource limits» | превышено процессорное время запроса: напишите разработчику, приложив адрес страницы |
